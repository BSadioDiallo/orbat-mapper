# The Angular app reuses the shared domain code unchanged, on Vue's reactivity engine

The Angular 22 app (`apps/web`) consumes the framework-independent code of `src/` (models, scenario store, domain actions, import/export, symbology, geo) through TypeScript path aliases, without editing it. The few modules that code imports from the Vue ecosystem are substituted at build time, like the `STANDALONE_MODULES` table of the singlefile build: `vue` maps to `@vue/reactivity` (the reactivity engine alone, no rendering runtime) with Vue's `watch` flush timing, `@vueuse/core` and `pinia` map to small faithful shims, and `@/scenariostore/localdb` maps to an adapter that goes through `ScenarioRepository`. Angular reads the store through `reactiveSignal`, a lazy `computed` that tracks both the store's reactive fields and Angular signals.

Rewriting the store and domain modules as immutable signals was rejected: thousands of lines rely on in-place mutation of `reactive` proxies, and the rule of the migration is to keep that logic as is. Writing an in-house reactivity engine was rejected as a reimplementation of Vue's. The cost is that `@vue/reactivity` remains a dependency of the Angular app; removing it means moving the domain to a framework-free store first, with the domain tests and the data parity test (`apps/web/src/app/testing/parity.spec.ts`) as the safety net.
